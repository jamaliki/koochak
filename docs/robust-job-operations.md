# Robust job operations

Operator path for Hierarchical Kaveh campaigns submitted through Koochak and Scruffy.
Replace `<...>` with target-allocation values, never old campaign values.
## Mental model

- **Koochak** prepares the immutable run (config, committed command, strict profile,
  manifests, checkpoints, typed outputs) and owns interruption plus validated resume.
- **Scruffy** is the asynchronous queue inside one Slurm allocation; it owns
  placement, gates, handover, evacuation, health, and bounded recovery.
- **Pazuzu** stages the same prepared run as a standalone Slurm job when no
  Scruffy allocation is suitable. Choose one backend for a prepared run.
## One-time setup and the profile contract

1. Install Koochak/Hierarchical Kaveh and expose the exact Scruffy site source at one
   absolute path on controller, submitter, and compute nodes.
2. Set one shared queue root/project. `SCRUFFY_ROOT` needs atomic rename and
   cluster-coherent `flock`; local-only locking is unsafe.
3. Export `SCRUFFY_SITE` to the import root containing `scruffy`; a login-node install
   or ambient `PYTHONPATH` is not a worker handoff because workers use `python -I`.

```bash
export SCRUFFY_ROOT="/shared/path/to/scruffy-queue"
export SCRUFFY_PROJECT="project-name"
export SCRUFFY_SITE="/shared/path/to/scruffy/site"
scruffy --version                        # from a source checkout: uv run scruffy --version
scruffy --root "$SCRUFFY_ROOT" summary --project "$SCRUFFY_PROJECT"
```

Every `EnvironmentProfile` used by a Scruffy task must include an explicit
`PYTHONPATH` with the Scruffy source **first**, and must declare the client:

```yaml
version: 1
id: <profile-id>
python: <absolute-python>
environment:
  set:
    PATH: <absolute-bin>:<absolute-python-bin>:/usr/bin:/bin
    PYTHONPATH: <SCRUFFY_SITE>:{cwd}/external/koochak:{cwd}
    KOOCHAK_SCRUFFY_ARTIFACT_ACK_TIMEOUT_SECONDS: "30"
requirements:
  packages:
    scruffy: "*"
    koochak: "*"
```

The profile is strict: absolute paths and explicit `PATH` are required, runtime-owned
`SCRUFFY_*` variables cannot be overridden, and unknown fields/interpolation are
rejected. Pass `Path(os.environ["SCRUFFY_SITE"])` to the profile builder and verify
`import scruffy` on compute, not only on the submit host.
## Prepare and submit one complete DAG

Keep the submission program and launch scripts committed. Build every `PreparedRun`,
then one `PreparedWorkflow`, and call `submit_scruffy_workflow(workflow, root=...)`
once; it stages all manifests before Scruffy admits the workflow, so admission is all-or-none.

```python
from pathlib import Path
from koochak.jobs import PreparedTask, PreparedWorkflow, submit_scruffy_workflow

workflow = PreparedWorkflow(
    request_id="<project>/<campaign>/v1", workflow_id="<campaign-v1>",
    project_id="<project>",
    tasks=(
        PreparedTask("trainer", train_run, resources_gpu, recovery={
            "max_attempts": 3,
            "retry_on": ["allocation_replaced", "allocation_incarnation_changed", "evacuated"],
            "evacuation": {"signal": "USR1", "grace_seconds": 600},
        }),
        PreparedTask("sampler", sample_run, resources_gpu, wait_for=({
            "kind": "artifact", "task_id": "trainer",
            "artifact_id": "checkpoint/step000100000.pt",
        },)),
        PreparedTask("analysis", analysis_run, resources_cpu, wait_for=({
            "kind": "artifact", "task_id": "sampler",
            "artifact_id": "samples/<immutable-id>",
        },)),
    ),
)
result = submit_scruffy_workflow(workflow, root=Path("<SCRUFFY_ROOT>"))
```

Use `needs=[{"task_id": "...", "condition": "succeeded"}]` only when producer
success is required; use exact typed `wait_for` conditions for checkpoints,
samples, folds, and analysis. Numbered checkpoints such as
`checkpoint/step000100000.pt` are immutable; `latest.pt` is not a dependency.
Declare every non-checkpoint output and publish its ready manifest.

For a JSON workflow generated by a committed tool, preflight and submit with:

```bash
scruffy --root "$SCRUFFY_ROOT" validate-workflow "workflow.json"
scruffy --root "$SCRUFFY_ROOT" submit-workflow "workflow.json"
```

Do not loop over individual submissions for a DAG. Keep request IDs stable for identical
retries: a repeated identical ID deduplicates, while changed argv/resources/dependencies/
profile with that ID is rejected.
## Checkpoints, evacuation, and retry

With Scruffy worker variables present, Koochak attaches `make_scruffy_hooks()`.
Set `KOOCHAK_SCRUFFY_ARTIFACT_ACK_TIMEOUT_SECONDS` (or pass
`artifact_ack_timeout_s=`) for gated tasks. Numbered checkpoint publication
uses `wait=True`; rejected/timed-out acknowledgement fails closed, leaving the
downstream task blocked. Lifecycle and progress events remain asynchronous.

To arm a deliberate evacuation for a precise milestone before it is published:

```bash
scruffy --root "$SCRUFFY_ROOT" evacuate \
  --project "$SCRUFFY_PROJECT" --workflow "WORKFLOW_ID" \
  --after-task trainer --after-artifact checkpoint/step000100000.pt \
  --request-id "EVACUATION_REQUEST_ID"
```

Arming does not pause launches; acknowledgement of that exact artifact starts
the normal evacuation. For an immediate scoped evacuation:

```bash
scruffy --root "$SCRUFFY_ROOT" evacuate \
  --project "$SCRUFFY_PROJECT" --workflow "WORKFLOW_ID" \
  --wait --resume-after --request-id "EVACUATION_REQUEST_ID"
```

Use `--job <job-id>` for one target. Without `--request-id`, the CLI prints a
generated ID before submitting; reuse that ID if the result is uncertain.
`--resume-after` clears the evacuation drain only after every target completed
or queued an eligible retry. A partial/timed-out operation remains drained.

Enable automatic pre-deadline evacuation when starting the allocation
controller:

```bash
scruffy --root "$SCRUFFY_ROOT" serve \
  --evacuate-before-end-seconds "EVACUATION_SECONDS"
```

The same state machine sends `USR1` only to policy-enabled workers. Koochak
finishes the update, atomically writes a numbered terminal checkpoint/manifest,
waits for strict acknowledgement, flushes hooks, and exits 75. Scruffy records
`failed`/`reason=evacuated` and creates at most one successor when `retry_on`
contains `evacuated` and budget remains. Allocation replacement/incarnation
changes use the same policy. The successor reruns the immutable command;
`--resume auto` selects the highest valid numbered checkpoint (or step zero),
never `latest.pt` or incomplete scaffolding.

If the controller is restarted in the same allocation, inspect first and run
`scruffy resume`; do not resubmit attached jobs. For a replacement allocation,
reuse the durable queue root, start with `serve --start-paused`, inspect the
handover, then resume.
## Monitor and diagnose

```bash
scruffy --root "$SCRUFFY_ROOT" summary --project "$SCRUFFY_PROJECT"
scruffy --root "$SCRUFFY_ROOT" running --project "$SCRUFFY_PROJECT"; scruffy --root "$SCRUFFY_ROOT" blocked --project "$SCRUFFY_PROJECT"
scruffy --root "$SCRUFFY_ROOT" explain "JOB_ID"
scruffy --root "$SCRUFFY_ROOT" logs "JOB_ID" --stream stderr --tail 200
scruffy --root "$SCRUFFY_ROOT" wait "JOB_ID" --timeout "TIMEOUT_SECONDS"
```

For incremental monitoring, keep a private cursor per observer:

```bash
CURSOR=$(scruffy --root "$SCRUFFY_ROOT" summary --project "$SCRUFFY_PROJECT" | jq -r .as_of_cursor)
scruffy --root "$SCRUFFY_ROOT" observe --after "$CURSOR" --wait 30 > observe.json
CURSOR=$(jq -r .next_cursor observe.json)  # persist this private cursor
# If .more is true, page immediately; if .reset is true, rebuild from overview.
```

Prefer MCP `overview`, `queue`, `running_jobs`, `blocked_jobs`, `resources`,
`inspect_job`, `tail_job_output`, `wait_job`, and `wait_for_updates` over shell
polling. Replace every returned `next_cursor`; cursors are opaque and must not
be shared between agents. The snapshot/lifecycle state is authoritative;
stdout, stderr, and workload annotations are observations only.
Interpret failures as follows: `blocked` means an unsatisfied dependency, `skipped`
means a required-success dependency ended unsuccessfully, `failed` needs its reason,
and `lost` means unresolved allocation/controller loss. Missing strict artifact
evidence leaves consumers blocked. Retry only an identical uncertain submission with
its same request ID, or a terminal non-success task with a new ID and same workflow/task.
Do not retry ordinary application exits merely because logs look transient.
## Never do this

- Do not SSH to compute nodes to launch, signal, or inspect worker processes.
- Do not make `latest.pt`, a directory, or a shell-created marker a dependency.
- Do not put `sleep` loops or filesystem polling in blocked jobs or operators.
- Do not reuse a request ID after changing the request specification.
- Do not cancel the outer Slurm allocation to evacuate a worker; use Scruffy.
- Do not launch out-of-band GPU work against Scruffy's inventory.
